哪些遊戲用到 DP？
Bachet's Game 和 21點報數 的核心都是同一個 DP 問題，只是換了一層外殼。 DP 的目的是找出每個「狀態」是必贏（W）還是必輸（L）。
狀態定義與轉移
定義 dp[n] = 當剩餘數字（或石頭數）為 n 時，當前輪到的玩家是 W 還是 L。
Python 
# Bachet's Game / 21點報數 通用 DP 解
def solve_dp(n: int, max_take: int) -> list:
    # dp[i] = True 表示當前玩家「必贏」
    dp = [False] * (n + 1)
    dp[0] = False  # 0個石頭 → 上個人已輸，輪到自己是贏
    dp[1] = False  # Misère: 只剩1顆必須取 → 必輸

    for i in range(2, n + 1):
        # 若存在某個取法使對手陷入 L，則當前是 W
        dp[i] = any(
            not dp[i - take]
            for take in range(1, min(max_take, i) + 1)
            if i - take >= 1  # 不能把所有石頭取完（Misère）
        )
    return dp

# 觀察 dp 陣列：(n=21, max_take=3)
# n: 1  2  3  4  5  6  7  8  ...
# dp: L  W  W  W  L  W  W  W  L  ...  ← 每 (max_take+1) 循環一次！
💡 關鍵觀察：從 DP 到 O(1)

跑完 DP 後會發現週期性規律：每隔 K = maxTake + 1 格，必輸位置就重複出現一次。 這讓我們可以把 O(N) 的 DP 化簡成一行公式：

n % (maxTake + 1) == 1 → 當前玩家必輸

這個「DP 推導規律 → 數學公式」的過程在演算法競賽裡非常常見。

最優走法公式
Python 
def best_move(stones: int, max_take: int) -> int:
    if stones == 1:
        return 1  # 強制輸，沒得選

    k = max_take + 1
    remainder = stones % k

    if remainder == 1:
        # 已在敗局，隨便取（這局輸了）
        return 1

    # 取 (remainder-1) 讓對手面對 stones % k == 1
    take = (remainder - 1) if remainder > 0 else k - 1
    return max(1, min(take, max_take, stones - 1))
Bitwise XOR Sprague-Grundy Theorem Nim-value
從單堆到多堆：為什麼需要 XOR？
Bachet's Game 是單堆 Nim，策略是 n % (M+1)。 但當有多堆石頭，每次只能從某一堆取時，這個公式就不夠用了。 需要用到位元互斥或（XOR / Nim-sum），這是 Nim 多堆版的核心。
Nim-sum（XOR）策略
📐 Bouton 定理（1901年）

設各堆石頭數為 a₁, a₂, ..., aₖ，定義 Nim-sum = a₁ XOR a₂ XOR ... XOR aₖ。

Nim-sum = 0 → 當前玩家必輸（L position）
Nim-sum ≠ 0 → 當前玩家必贏（W position）

必勝走法：找到一堆，取走若干顆，使得取完後所有堆的 XOR 變為 0。

Python 
def nim_is_losing(heaps: list) -> bool:
    """Nim-sum = 0 表示當前玩家必輸"""
    nim_sum = 0
    for h in heaps:
        nim_sum ^= h          # XOR 每一堆
    return nim_sum == 0

def nim_best_move(heaps: list) -> tuple:
    """回傳 (堆的 index, 要取走的數量)"""
    nim_sum = 0
    for h in heaps:
        nim_sum ^= h

    if nim_sum == 0:
        # 敗局，隨便取（對手完美時必輸）
        for i, h in enumerate(heaps):
            if h > 0: return (i, 1)

    for i, h in enumerate(heaps):
        target = h ^ nim_sum      # 取完後這堆應剩幾顆
        if target < h:            # 合法（只能減少）
            return (i, h - target) # 取走 (h - target) 顆

# 範例：[3, 5, 7]
# Nim-sum = 3 XOR 5 XOR 7 = 011 XOR 101 XOR 111 = 001 = 1 ≠ 0 → 先手贏
# best_move → 從第3堆(7顆)取6顆，留1顆，使 3 XOR 5 XOR 1 = 7... 不對
# 正確：target = 7 XOR 1 = 6，但 6 < 7，取走 1 顆 → [3,5,6] XOR=0 ✓
為什麼 XOR 可以判斷勝負？直覺解釋
XOR 有一個關鍵性質：a XOR a = 0，以及a XOR 0 = a。 可以把每堆石頭的數量寫成二進位，然後對每個位元逐一看： 如果每個位元上 1 的個數都是偶數，XOR 就是 0（必輸位置）。 必勝走法就是讓某個位元上奇數個 1 變成偶數個。
Example 
# [3, 5, 6] 的二進位
#  3 = 011
#  5 = 101
#  6 = 110
# XOR = 000  ← 每個位元上 1 的個數都是偶數 → 必輸位置！

# [1, 2, 3] 的二進位
#  1 = 01
#  2 = 10
#  3 = 11
# XOR = 00  ← 必輸位置

# [1, 2, 4] 的二進位
#  1 = 001
#  2 = 010
#  4 = 100
# XOR = 111 = 7 ≠ 0 → 必贏，可從任一堆取到讓 XOR=0
Sprague-Grundy 定理（更一般化的理論）
Nim 是所有組合賽局的基礎。Sprague-Grundy 定理說的是： 任何一個「公平賽局（impartial game）」都等價於某個大小的 Nim 單堆。 這個「等價大小」叫做 Grundy value（或 nimber），記作 G(s)。
Python 
from functools import lru_cache

def grundy(n: int, max_take: int) -> int:
    """計算 Bachet's Game 各狀態的 Grundy value"""
    @lru_cache(maxsize=None)
    def g(state):
        if state == 0: return 0  # 終止狀態
        # mex = minimum excludant（最小未出現的非負整數）
        reachable = {g(state - t) for t in range(1, min(max_take, state) + 1)}
        mex = 0
        while mex in reachable:
            mex += 1
        return mex
    return g(n)

# Grundy value = 0 ↔ 必輸位置（等價於 Nim 空堆）
# 多個獨立子遊戲合在一起時：G(整體) = G(子遊戲1) XOR G(子遊戲2) XOR ...
# 這就是為什麼多堆 Nim 用 XOR！
🔗 所有遊戲的統一理論

Bachet → Grundy value 週期為 maxTake+1
21點報數 → 同上，只是換了外殼
Nim 多堆 → 每堆 Grundy value 即堆的大小，整體 XOR
Chomp → Grundy value 未知（開放問題）

Sprague-Grundy 是這些遊戲背後共同的數學語言。 這個定理讓你可以把任意組合賽局都轉換成 Nim 來解， 是組合賽局理論最核心的結果。

Golden Ratio Beatty's Theorem O(1) Formula
Wythoff's Game 規則
有兩堆石頭，兩人輪流，每次可以： 從任一堆取任意數量（至少1顆）， 或從兩堆同時取相同數量。 取走最後一顆石頭的人贏（Standard 規則）。
必敗位置（Cold positions）
Wythoff's Game 的必敗位置有一個令人驚訝的規律， 直接和黃金比例 φ = (1+√5)/2 ≈ 1.618 有關：
φ Wythoff 定理（1907年）

所有必敗位置 (a, b)（a ≤ b）都是以下形式：

aₙ = ⌊n·φ⌋，bₙ = ⌊n·φ²⌋ = aₙ + n

其中 φ = (1+√5)/2，φ² = φ+1 ≈ 2.618，n = 0, 1, 2, 3, ...

前幾個必敗位置：(0,0), (1,2), (3,5), (4,7), (6,10), (8,13), ...

Python 
import math

PHI = (1 + math.sqrt(5)) / 2   # ≈ 1.6180339887

def wythoff_is_losing(a: int, b: int) -> bool:
    """判斷 (a, b) 是否為必輸位置（a ≤ b）"""
    if a > b: a, b = b, a     # 確保 a ≤ b
    n = b - a                  # n = b - a
    return int(n * PHI) == a   # ⌊n·φ⌋ == a 表示必輸

def wythoff_best_move(a: int, b: int):
    """找必贏走法，回傳操作後的 (a', b')"""
    if wythoff_is_losing(a, b):
        return None  # 已在必輸位置，沒有好走法

    # 嘗試所有合法移動找到必輸位置
    for na in range(a + 1):       # 從堆A取石頭
        if wythoff_is_losing(na, b): return (na, b)
    for nb in range(b + 1):       # 從堆B取石頭
        if wythoff_is_losing(a, nb): return (a, nb)
    for d in range(1, min(a, b) + 1):  # 兩堆各取 d 顆
        if wythoff_is_losing(a - d, b - d): return (a - d, b - d)

# 複雜度：O(max(a,b)) 掃描找走法，O(1) 判斷每個位置
黃金比例為什麼出現在這裡？
關鍵是 Beatty 定理：對於無理數 r 和 s， 若 1/r + 1/s = 1，則 {⌊n·r⌋} 和 {⌊n·s⌋} 恰好把所有正整數不重複地分成兩組。 由於 1/φ + 1/φ² = 1，序列 ⌊n·φ⌋ 和 ⌊n·φ²⌋ 就剛好把所有非負整數配成對，完美對應了 Wythoff 的必敗位置。
Analysis 
# Beatty 定理驗證
# φ ≈ 1.618,  φ² ≈ 2.618
# 1/φ + 1/φ² = 0.618 + 0.382 = 1 ✓

# ⌊n·φ⌋  序列 (n=1,2,...): 1, 3, 4, 6, 8, 9, 11, 12, 14, ...
# ⌊n·φ²⌋ 序列 (n=1,2,...): 2, 5, 7, 10, 13, 15, 18, 20, 23, ...
# 兩序列合起來 = 所有正整數，且不重複 ✓

# 必敗位置：
# n=1: (1, 2)  → 1 XOR 2 = 3，但這是 Wythoff 不是 Nim
# n=2: (3, 5)
# n=3: (4, 7)
# n=4: (6, 10)
✨ 為什麼 Wythoff 比 Nim 更難？

Nim 多堆的必勝策略來自位元運算，可以直接計算。
Wythoff 的必勝策略涉及無理數（黃金比例）， 雖然也有 O(1) 公式，但背後的數學遠比 XOR 深。

從演算法角度看：兩者都是 O(1) 判斷必敗位置， 但 Wythoff 在「找最佳走法」時需要 O(max(a,b)) 掃描， 而 Nim 可以用 XOR 直接算出最佳走法，是 O(堆數)。

Minimax Memoization Alpha-Beta Pruning
Chomp 為什麼要用 Minimax？
Chomp 的狀態空間太大，沒有已知的 O(1) 公式（這是一個開放數學問題！）。 我們必須用搜尋樹（博弈樹）枚舉所有可能，找出必贏的走法。 這和西洋棋程式（如 Stockfish）的核心邏輯完全相同。
Minimax 遞迴定義
Python 
from functools import lru_cache

def chomp_solver(rows: int, cols: int):
    # 棋盤用 frozenset 表示存活的格子 (r, c)
    # (0,0) 是毒格（左下角）

    @lru_cache(maxsize=None)
    def is_losing(board: frozenset) -> bool:
        """當前玩家是否在必輸位置"""
        # 只剩毒格 → 當前玩家必須吃它 → 必輸
        non_poison = {(r,c) for r,c in board if (r,c) != (0,0)}
        if not non_poison:
            return True

        # 嘗試所有合法移動：若能讓對手陷入必輸 → 我必贏
        for (r, c) in non_poison:
            eaten = frozenset(
                (rr, cc) for rr, cc in board
                if not (rr >= r and cc >= c)
            )
            if is_losing(eaten):
                return False  # 找到必贏走法 → 當前不是輸

        return True  # 所有走法都讓對手贏 → 我必輸

    initial = frozenset(
        (r, c)
        for r in range(rows)
        for c in range(cols)
    )
    return is_losing(initial)

🔬 記憶化（Memoization）的關鍵

不同的走法序列可能產生相同的棋盤狀態。 如果不做記憶化，同一個狀態會被重複計算指數次。 用 dict 或 @lru_cache 把已算過的狀態存起來， 可以讓時間從 O(moves!) 降到 O(唯一狀態數 × 合法移動數)。

Alpha-Beta Pruning（進階）
在大棋盤上，狀態空間仍然太大。Alpha-Beta Pruning 是 Minimax 的優化版本， 透過剪掉「不可能被選到的分支」，在不影響正確性的情況下大幅加速。 這是現代西洋棋程式、圍棋程式的基礎之一。
Python 
def minimax(state, is_maximizing, alpha, beta):
    if is_terminal(state):
        return evaluate(state)

    if is_maximizing:
        value = -float('inf')
        for move in get_moves(state):
            value = max(value, minimax(apply(state, move), False, alpha, beta))
            alpha = max(alpha, value)
            if beta <= alpha: break  # β 剪枝
        return value
    else:
        value = float('inf')
        for move in get_moves(state):
            value = min(value, minimax(apply(state, move), True, alpha, beta))
            beta = min(beta, value)
            if beta <= alpha: break  # α 剪枝
        return value

🤯 Chomp 的特殊地位

Chomp 在數學上已被證明先手必勝（用 Zermelo's Theorem）， 但目前沒有人知道具體策略是什麼（除了少數特殊棋盤大小）。 這是組合賽局理論（Combinatorial Game Theory）中的著名開放問題之一。 這也是為什麼「困難」電腦在大棋盤上可能表現不如預期—— 這個問題連數學家也還沒完全解決！

桌上有 N 顆石頭，兩人輪流取，每次取 1~M 顆。取走最後一顆的人輸（Misère 規則）。
🔢 21點報數
兩人輪流從 1 開始往上報數，每次可報 1~M 個。說到目標數字者輸。本質與 Bachet's Game 完全相同！
🍫 Chomp
一塊 M×N 巧克力，左下角是☠️毒格。點擊一格，該格及右方、上方所有格都被吃掉。被迫吃毒格者輸。數學上先手必勝，但沒有已知通用策略！
